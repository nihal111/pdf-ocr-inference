# Raw evaluator reports

- `baseline.json`: the original accepted vLLM batch-1 baseline.
- `optimized.json`: the best retained configuration's final verification.
- `comparison.json`: regenerated by `eval/compare.py` from those two files.
- `baseline-env.json` and `optimized-env.json`: each report's recorded environment.
- `provenance.json`: original file paths, SHA-256 digests, and measurement settings.

The baseline and optimized reports are unchanged copies of the existing
measurements, not new timing runs of the API contract fixes. Both use the same
five frozen PDFs (20 pages), references, four NVIDIA L4 GPUs, one warm-up and five
measured calls per PDF, sequential calls, and a cosine threshold of 0.99.
The recorded timeout is 1,800 seconds, an allowed override of the 600-second default.
Latencies remain in milliseconds as required by the evaluator's raw schema.

From the repository root, activate the project's Python 3.12 environment; the
host's default `python3` is older than the required Python 3.10:

```bash
source .venv/bin/activate
python3 --version
python3 -m unittest discover -s eval/tests
python3 -m pytest tests/test_pdf_contract.py tests/test_worker_render.py tests/test_page_parallel.py
python3 eval/compare.py \
  --baseline reports/baseline.json \
  --optimized reports/optimized.json \
  --out reports/comparison.json
```

The frozen dataset manifest is `data/public-v3/manifest.json`; its paths are
relative to `--root data/public-v3`. All listed page counts were checked against
the actual PDFs. References already exist and must not be overwritten.
For a new reference capture, use a separate manifest with unused reference paths.

Both measured variants expose `document_pipeline.adapter.embed_pdf`; their
pipeline settings are selected by `DOCUMENT_PIPELINE_CONFIG`. Engine and precision
may differ between variants; hardware identity and sequential PDF concurrency
must match. Set `CUDA_VISIBLE_DEVICES` to the assigned GPUs before running any
inference, using the existing isolated project environments.
